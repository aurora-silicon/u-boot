# Aurora U-Boot 0.1.0

The first Aurora Silicon release of U-Boot for Apple Silicon. Aurora's version series starts at 0.1.0; the underlying U-Boot version is **2026.07**.

## Origin and integration

The shared upstream ancestor is U-Boot [`ece349ade297`](https://github.com/AsahiLinux/u-boot/commit/ece349ade2973e220f524ce59e59711cc919263f), which prepares v2026.07. Aurora builds on Asahi Linux's Apple Silicon port. This release establishes `main` from the complete `aurora-wip` history through [`0cb6fed6a105`](https://github.com/aurora-silicon/u-boot/commit/0cb6fed6a10512d1013a4a80b6d83c3d56140f2f), retaining `aurora-stable` and the development branches.

## Changes

### MacBook Neo / A18 Pro (T8140, J700)

- Map every inherited DRAM bank, retain LMB/EFI access, and add the A18 Pro peripheral map.
- Add DockChannel UART console support, named data windows, and bounded transmit backpressure.
- Adopt the live post-M4 ANS/NVMe session instead of resetting the coprocessor. Support larger I/O queues, controller-specific queue setup, correct TCB direction, and live-session handoff with queue retirement.
- Roll back queue counts on rejected creation, block reuse after a timed-out command, and flush the volatile write cache after writes.
- Respect firmware-owned/locked DARTs, fix T8110 invalidation, and preserve inherited active PMGR domains.
- Bring up A18 Pro USB2 host mode, validate ATC tunables, propagate startup/shutdown failures, and restore clocks/retry incomplete shutdown.
- Leave unsupported T8140 PCIe probing to the OS. Enable `sysboot` and `bootmenu`, with the internal ESP EFI application first in the J700 boot route.
- Set the X bits in U-Boot console colors and honor padded framebuffer stride in EFI GOP. The console-color fix does not cover every direct-framebuffer/BMP/GOP client.
- Extend MTP/RTKit startup, announced HID interfaces, word-wide DockChannel transfers, buffer mapping, and persistent helper OSLog preservation. Keep the T8140 MTP session running across handoff and re-enable the MTP keyboard in the shared default configuration.

### M5 and M6

- Add T8142/J813 and T8152/J873g memory maps and RAM-boot support, shared DockChannel console fixes, and documented RAM/framebuffer Linux handoff.
- Keep J813's MTP cold for Linux.
- Provide a separate `apple_j873_defconfig` for the M6 RAM-boot path, with automatic boot and persistent EFI variable storage disabled. Record the earlier operator-confirmed USB-C Linux console result; EFI and persistent boot remain unqualified for this configuration.

### Other platforms and release infrastructure

- Incorporate Apple M3 Pro/Max (`t6030`, `t6031`, `t6034`) and `t8122` ATC PHY compatibility.
- Accept both string and integer FDT bootdelay overrides and normalize shared board configuration.
- Add strict CI builds for the shared Apple and M6 configurations, packaged binaries and matching debug symbols, exact source/configuration manifests, licenses, SHA-256 checksums, and automatic **draft** GitHub releases.

## Artifacts

- `u-boot-v0.1.0-apple_m1.zip`: shared Apple build, including the Neo/M5 code paths and the current default MTP keyboard setting.
- `u-boot-v0.1.0-apple_j873.zip`: separate M6 RAM-boot configuration.
- Each archive contains `u-boot-nodtb.bin`, its deterministic gzip payload, `u-boot.bin`, `u-boot.dtb`, the exact `.config`, licenses, build metadata, and checksums.
- Matching `*-debug.zip` archives contain the ELF image, symbol list, and linker map. `SHA256SUMS` checks the downloadable archives.

Use the **nodtb** payload with matching Aura and board-specific DTBs. The embedded/control DTB in these configurations defaults to `t8103-j274`; it is not a Neo, M5, or M6 DTB. These archives are separate components, not a complete UEFI `boot.bin` bundle.

## Qualification and remaining work

These exact release artifacts have not been boot-tested on hardware. Earlier board-specific results do not qualify the new release as a whole. M6 storage, USB, networking, keyboard, SMP, EFI and persistent boot retain the documented qualification limits. The T8140 MTP handoff still has a separately reviewed transactional fix in [PR #6](https://github.com/aurora-silicon/u-boot/pull/6); it remains outside this release pending its hardware checks.
