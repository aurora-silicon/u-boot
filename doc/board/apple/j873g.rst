Apple M6 Mac mini (J873g)
=======================

The initial T8152 port boots from RAM using the firmware-selected DockChannel
UART. Build with ``make apple_j873_defconfig`` followed by ``make`` using an
AArch64 GNU toolchain. Supply an external FDT from m1n1; the built-in M1 DT does
not describe this board. The root must include ``apple,j873g`` and ``apple,t8152``.
Use ``u-boot-nodtb.bin`` for RAM handoff.

The FDT must describe one contiguous usable RAM bank, reserve the resident loader
and all live allocations, and supply the inherited simple framebuffer if used.
The UART uses ``apple,dockchannel-uart`` with named ``config`` and ``data``
register ranges and ``bootph-all``. The measured console windows are
``0x308128000`` and ``0x30812c000`` (each 16 KiB). Set ``/chosen/stdout-path`` to
that node. Only the DockChannel I/O aperture is initially mapped.

Storage, USB, networking, keyboard, SMP and EFI operating-system boot remain
unqualified. Automatic boot and persistent EFI variable storage are disabled.
Preserve the installed recovery loader.

The generic Apple board code still links the USB and NVMe drivers. Leave these
devices absent or disabled in the handoff FDT; their presence in the binary is
not a claim of T8152 support.

End-to-end qualification
------------------------

Failure cases to check include a mismatched board, incorrect UART window,
missing RAM or framebuffer mappings, relocation into a live loader allocation,
lost console characters and broken return from an EFI payload. A compile alone
does not rule these out.

From a fresh single-CPU m1n1 session on chip ``0x8152``, board ``0x24``, target
``J873g`` / model ``Mac18,5``, hash the candidate, upload to reserved RAM, and
verify complete readback. Enter with caches/MMU off and the FDT in x0. Capture
the banner and prompt, then run ``version``, ``bdinfo``, ``printenv`` and
``echo J873_UBOOT_E2E_PASS``. Save the source commit, binary/FDT hashes, console
log and result receipt. Verify the RAM map and command responses after relocation;
the marker alone is insufficient.

The existing Linux M6 initial boot used a retained m1n1 loader and direct Linux
handoff. It is not evidence of booting through this U-Boot source.
