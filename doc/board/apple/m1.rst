U-Boot for Apple Silicon Macs
=============================

Allows Apple Silicon Macs to boot U-Boot via the m1n1 bootloader
developed by the Asahi Linux project.  At this point the machines with
the following SoCs work:

 - Apple M1 SoC (t8103)
 - Apple M2 SoC (t8112)
 - Apple M1 Pro SoC (t6000)
 - Apple M1 Max SoC (t6001)
 - Apple M1 Ultra SoC (t6002)
 - Apple M2 Pro SoC (t6020)
 - Apple M2 Max SoC (t6021)
 - Apple M2 Ultra SoC (t6022)

On these SoCs the following hardware is supported:

 - S5L serial port
 - SPI keyboard (on M1 laptops)
 - Framebuffer
 - NVMe storage
 - USB 3.1 Type-C ports

Device trees are provided in dts/upstream/src/arm64/apple/ and available
for all M1 and M2 (t8103, t8112, t600x and t602x) devices.

Initial M5 J813 native boot
--------------------------

The M5 MacBook Air (J813, T8142) additionally supports RAM-loaded native
Linux boot with the firmware framebuffer and DockChannel console. Its
memory map covers the ADT-measured I/O aperture from ``0x210000000`` to
``0x600000000``. m1n1 supplies the usable RAM bank and framebuffer mapping
through the FDT; DRAM starts at ``0x10000000000``.

Use ``apple_m1_defconfig`` and ``u-boot-nodtb.bin`` with the J813 DTB from
the companion Linux support. m1n1 must fill that DTB before entering U-Boot.
The DT's named DockChannel ``data`` window provides the serial console.
m1n1's string-valued ``/config/bootdelay`` is accepted alongside the existing
integer form, allowing an unattended RAM ``booti`` command.

Validate using a RAM-only initramfs and ``maxcpus=1``. Record source commits,
binary hashes, payload readbacks and the serial boot log. At the Linux shell,
verify the kernel/config identity, CPU0, framebuffer registration, advancing
uptime and architectural timer interrupts over ``sleep 5``, and RAM-only
mounts. Repeat from a fresh firmware boot and retain both captures.
This initial J813 path does not qualify storage, USB host devices, input,
networking, native GPU/display drivers or SMP. The existing M1/M2 hardware
support list above does not apply to J813.

M4 J713 boot
------------

J713/T8132 uses ``apple_m1_defconfig`` and ``u-boot-nodtb.bin``. The control
DT used for building is not the runtime DT: m1n1 supplies the J713 tree,
its usable DRAM banks, firmware reservations and inherited framebuffer.
The T8132 map includes the ANS/NVMMU, PCIe and both ATC apertures; every
incoming DRAM bank is mapped before EFI can allocate from it.

This is the bootloader companion to the basic Linux support in
https://github.com/aurora-silicon/linux/pull/366 and the m1n1 review
branch at https://github.com/aurora-silicon/m1n1/tree/m4/pr1-basic-bringup.
The firmware resource handoff supports the basic framebuffer boot and
later native graphics without activating a GPU or DCP driver here.

J713 uses the shared internal-ESP EFI boot flow: the ESP UUID supplied by
m1n1 selects ``EFI/BOOT/BOOTAA64.EFI``, with the prepared runtime FDT.
Saved environment overrides remain effective.

The shared post-M4 NVMe driver adopts the live ANS firmware session and
keeps it running at OS handoff. Do not reset that coprocessor or reclaim
its firmware buffers between m1n1, U-Boot and Linux. Native GPU and DCP
firmware mappings remain owned by the OS drivers.

Initialize J713's RTKit helper, retain its buffers and bypass stream, and
publish the inherited-session marker for Linux. Leave DockChannel discovery
and HID configuration to Linux. Late mailbox startup must finish until a HID
header is pending before publishing that marker. Firmware DRAM buffers are
described by no-map reserved-memory nodes, consumed by both the EFI memory map
and Linux. The helper's ``memory-region`` references these DRAM reservations.
``apple,rtkit-buffers`` contains five-cell tuples: endpoint, address high/low,
exact protocol byte size and the original request's ``is_mapped`` flag. The
last flag records whether firmware supplied the address; SRAM placement is
validated independently. The ``mtp-live-v1`` marker permits Linux to preload
that inventory before receiving RTKit traffic. The legacy inherited marker
remains for stable kernels that preserve the session without servicing it.
If optional input initialization or handoff fails, stop the helper
before freeing its buffers, disable its outgoing DT nodes and continue booting.
This retained input contract is qualified only for J713. The built-in MTP
keyboard is therefore unavailable in U-Boot; a USB keyboard can be used
for bootloader interaction after USB is started manually. USB keyboard
interaction has not been hardware-qualified by this series.

The per-UKI ``u-boot,j713-dtb-imported`` marker reports runtime import only;
optional input may still be disabled. Input qualification must separately check
``apple,rtkit-handoff = "mtp-live-v1"``, its buffer inventory and reservations,
the running ASC, and physical keyboard/trackpad response. A marker alone does
not establish that the coprocessor is live.

Building U-Boot
---------------

.. code-block:: bash

    $ export CROSS_COMPILE=aarch64-none-elf-
    $ make apple_m1_defconfig
    $ make

This will build ``u-boot-nodtb.bin`` as well as devices trees for some
of the supported machines.  These device trees can be found in the
``arch/arm/dts`` subdirectory of your build.

Image creation
--------------

In order to run U-Boot on an Apple Silicon Mac, U-Boot has to be used
as a payload for the m1n1 bootloader.  Instructions for building m1n1
can be found here:

    https://github.com/AsahiLinux/docs/wiki/SW%3Am1n1

.. code-block:: bash

    $ cat m1n1.macho t8103-j274.dtb u-boot-nodtb.bin > u-boot.macho

This uses ``u-boot-nodtb.bin`` as the device tree is passed to U-Boot
by m1n1 after making some adjustments.

Per-kernel J713 device trees
----------------------------

J713 may boot an OS-supplied DTB through ``EFI_DT_FIXUP_PROTOCOL``, including
the ``.dtb`` section of a systemd-stub unified kernel image. This lets a new
kernel use its own platform descriptions while older fallback kernels keep
the original DTB bundled with m1n1.

The shared ``apple_m1_defconfig`` enables ``APPLE_J713_FDT`` with the retained
MTP helper. Configurations for other Apple systems may omit this option and
keep their existing FDT padding and input configuration.

The OS tree opts in by supplying ``/chosen/u-boot,j713-dtb-source`` as a
NUL-terminated string containing its 40 lowercase hexadecimal source commit
characters. Both trees must identify J713 and T8132. U-Boot imports this boot's
CPU release slots, firmware memory reservations, ANS/SPMI resources, firmware
identities, PMP tunables, calibration, framebuffer and native graphics handoff.
References to reserved memory and display devices are translated to the OS
tree's phandles. PMGR ownership, power domains, pinctrl, clocks and all other
static topology remain the OS tree's descriptions.

The import is bounded to source trees and used OS-tree data of at most 128 KiB;
``SYS_FDT_PAD`` provides 256 KiB for the runtime additions. Unsupported address
cell layouts, missing CPU release slots, incomplete resource descriptions and
unknown reserved-memory properties cause refusal before the live input helper
is touched. The currently supported DMA-parent layout is the J713 structural
parent, without a ``dma-mem`` interconnect. A basic platform DTB may omit the
GPU and display devices; their firmware carveouts remain reserved without
references to the omitted devices. CPU configurations that differ from m1n1's
available set need explicit support rather than invented release addresses.

Import validation and allocation use a scratch tree. A failed import changes
neither the OS tree nor m1n1's control tree. The existing RTKit helper then
publishes its actual current input session, including explicit disabled input
if that optional initialization failed. After those fixups U-Boot publishes
``/chosen/u-boot,j713-dtb-imported = <1>``. Repeated preparation of the same
session is supported.

If a later candidate cannot describe an already-published input session,
its fixup fails so EFI can keep the prior device tree and live session.

systemd-stub may continue with its original firmware DTB if an embedded tree's
fixups fail. Qualification must therefore inspect both marker properties in
the running flattened device tree and inspect the new platform descriptions;
a successful kernel boot alone does not establish use of the new DTB.
The unmarked legacy path does not use this import.

J713 peripheral calibration export requires ``atcphy0`` and ``atcphy1``
aliases to the ``apple,t8132-atcphy`` nodes in m1n1's control DTB, and a
``bluetooth0`` alias to the ``pci14e4,5f72`` endpoint. Without matching
source nodes and calibration, Bluetooth remains disabled and no USB3
calibration is imported. An explicitly USB2-only OS port stays USB2;
calibration never adds registers or changes power ownership. Malformed
supplied calibration refuses the candidate transactionally.

Image installation
------------------

Instructions on how to install U-Boot on your Mac can be found at:

    https://github.com/AsahiLinux/docs/wiki/Developer-Quickstart

Just replace ``m1n1.macho`` with ``u-boot.macho`` in the instructions.

Debug UART
----------

Since the base address of the UART is SoC-dependent, the debug UART is
not enabled by default.  To enable the debug UART the base address
needs to be adjusted and the CONFIG_DEBUG_UART option needs to be
enabled.  The table below gives the correct base address for the
supported SoCs.

.. list-table::
   :widths: 32 16
   :header-rows: 1

   * - SoC
     - Base Address
   * - M1 (t8103) and M2 (t8112)
     - 0x235200000
   * - M1 Pro/Max/Ultra (t6000/t6001/t6002) and M2 Pro/Max/Ultra (t6020/t6021/t6022)
     - 0x39b200000
